# Day 17: 間接アドレッシング (`(zp,X)` / `(zp),Y`)

---

🌐 Available languages:
[English](./README.md) | [日本語](./README_ja.md)

## 📜 概要

今日は 6502 で最も複雑、かつ最も強力な**間接アドレッシング (Indirect Addressing)**を実装します。

これは、指定したメモリ番地に書かれている「さらに別のアドレス」を読み取って、そこへアクセスするモードです。C 言語などの「ポインタ」のハードウェア実装そのものであり、OS や本格的なアプリケーションの開発には欠かせません。

## 🧠 メモリ構成の注意

Day 10 以降はプログラムを Gowin BSRAM で実装した RAM (`ram.sv`) から実行します。Day 04〜09 の簡易 ROM とは構成が異なります。

## 🎯 学習目標

- **ポインタの概念**:「アドレスが入ったアドレス」を読み取る仕組みの理解。
- **インデックス付き間接**: `(zp,X)` と `(zp),Y` の動作の違いを学ぶ。
- **多段メモリアクセス**: 1 命令の中で何度もメモリ番地をフェッチする複雑なステート管理。

## 🏗️ 実装する命令（例）

```mermaid
graph TD
    subgraph "JMP (abs)"
        Instr[Instruction<br/>JMP $1000]
        Ptr[Pointer at $1000<br/>Contains $2034]
        Target[Target Address<br/>$2034]
        Instr -->|Fetch Pointer| Ptr
        Ptr -->|Jump to| Target
    end

    subgraph "LDA (zp),Y"
        ZP[ZP Address]
        Ptr2[Read Pointer from ZP]
        AddY{+ Y}
        Eff[Effective Address]
        ZP --> Ptr2
        Ptr2 --> AddY
        AddY --> Eff
    end
```

| オペコード | Mnemonic     | 説明                                         | サイクル数 |
| :--------: | ------------ | -------------------------------------------- | :--------: |
|   `0x6C`   | `JMP (abs)`  | 指定番地に書かれた 16bit アドレスへジャンプ  |     5      |
|   `0xA1`   | `LDA (zp,X)` | ポインタ計算 (zp+X) 後、その先の内容をロード |     6      |
|   `0xB1`   | `LDA (zp),Y` | ポインタ取得後、その値に Y を足してロード    |     5+     |

## 🛠️ 実装ステップ

1. **間接アドレスのフェッチ**:
    - オペランドで示された番地（例：ゼロページ）から 2 バイトを読み取り、一時的な 16 ビットアドレスレジスタに格納します。
2. **インデックスの加算**:
    - `(zp,X)`: ゼロページ内で X を足してからポインタを読み取ります。
    - `(zp),Y`: ポインタを読み取った後に Y を足して最終アドレスを決めます。
3. **複雑なステートマシンの実装**:
    - 1 つの命令で 5 ～ 6 サイクルを要するため、状態を細かく分けて制御します。

## 🧪 動作確認

- **テスト実行 (シミュレーション)**: 完成版の CPU テストはこのディレクトリで `make test-cpu` を実行します。共有テストベンチ `../day17/sim/tb_cpu.sv` が `LDA (zp,X)` / `LDA (zp),Y` / `JMP (abs)` (ゼロページラップや `JSR`/`RTS` との組み合わせを含む) を検証し、最終的に `PASS` と表示されます。`make sim` は TFT smoke test を実行します。`make test` はこれらに加えて同期 RAM 統合テストと LCD パイプラインテストも実行します。

- **実機プログラム (`rom.sv` の命令列)**:

    ```asm
    LDA #$20
    STA $10    ; $0010 番地に $20 を書く
    LDA #$80
    STA $11    ; $0011 番地に $80 を書く -> ポインタ $8020 完成

    LDY #$01
    LDA ($10),Y ; $8020 + 1 = $8021 番地から $42 をロード
    HLT
    ```

    読み出し先 `$8021` のデータ `$42` は ROM に埋め込まれており、CPU が初期化するものではありません。`make test-cpu` で使う共有テストベンチは、上記とは別のプログラムとポインタ表を注入します。

- **実機 (FPGA)**: LCD のデバッグ表示 (`PC:xxxx A:xx ...`) で `A:42` となり、`HLT` で停止することを確認します。
