# simple5 の初回算術を切り分ける実機診断

`examples/diag_simple5.s` は、`simple5.s` の最初の `LDA #$20`、`CLC`、`ADC #$01`、`CMP #$7F` を、`IFO` や `WVS` より先に一度だけ実行する。`CVR` で表示領域を消去し、`IFO $0200` でロード済みプログラムを約4秒表示する。その後 `IFO $0000` へ切り替え、`HLT` で零ページの結果を保持する。

| 場所 | 期待値 | 意味 |
| --- | --- | --- |
| RAM `$0001` | `$20` | `LDA #$20` の直後に保存した A |
| RAM `$0002` | `$21` | `CLC; ADC #$01` の結果 |
| RAM `$0003` | `$B0` | `CMP #$7F` 後の `PHP; PLA` 結果。N=1、V=0、B=1、bit 5=1、C=0、Z=0。I/D は reset 時に 0 |
| IFO の A | `$21` | `$0002` から読み戻した値 |

最初の `IFO $0200` は **RAM `$0200`–`$027F`** を表示する。ここで読めるのはロード済みプログラムのバイトであり、`$0001`–`$0003` の直接表示ではない。先頭は `CF A9 20 85 01 18 69 01 85 02 C9 7F 08 68 85 03 A5 02 DF 00 02 FF F0 DF 00 00 EF` の順になる。`$0202=$20`、`$0207=$01`、`$020B=$7F` は命令の**即値**であり、計算後の RAM `$0001`–`$0003` と混同しない。`WVS $F0` の後の `IFO $0000` は **RAM `$0000`–`$007F`** を表示し、`$0001`–`$0003` の実値を最後に残す。WVSの待ち時間は表示フレーム周期に依存する。

アセンブルだけを確認するには `make -C examples PROG=diag_simple5 diag_simple5.bin` を使う。実機へ書く場合は `make prog-download PROG=diag_simple5` を実行する。後者は `include/boot_program.sv` と bitstream を更新するため、今回の `simple5` 本体との比較では使用したプログラム名を記録する。

この診断で A=`$21`、RAM `$0001`–`$0003` が `20 21 B0` となり、元の `simple5` で `$20↔$5E` が続くなら、初回の算術より後の `IFO`、`WVS`、ループまたは表示更新をさらに切り分ける。診断が失敗しても、この表示だけでタイミング違反と断定できない。

## 黒画面の場合の短い診断

`diag_simple5` の実機表示が真っ暗だったため、その命令列は変更せず保存した。次の2本で `IFO` と `WVS` を分けて調べる。

| プログラム | 実行順 | 期待する画面・値 |
| --- | --- | --- |
| `diag_adc` | `CVR` → 右上に `S` → `LDA #$20; STA $01; CLC; ADC #$01; STA $02` → 右上に `!` → `IFO $0000` → `HLT` | RAM `$01=$20`、`$02=$21`、IFOのA=`$21`。`S` は進捗表示、最終的な右上は `!`。`WVS` は通らない。 |
| `diag_wvs` | `CVR` → 右上に `A` → `WVS $F0` → 右上に `B` → `HLT` | `A` が約4.1秒続いて `B` になり、そのまま残る。`ADC` と `IFO` は通らない。 |

それぞれのアセンブル確認は `make -C examples PROG=diag_adc diag_adc.bin`、`make -C examples PROG=diag_wvs diag_wvs.bin`。実機書込みは `make prog-download PROG=diag_adc` または `make prog-download PROG=diag_wvs`。`S` が表示されない場合は `CVR`、boot実行、右上VRAM表示を先に調べる。`S` から `!` に変わらない場合は初回算術経路に絞れる。`diag_wvs` が `A` のままならVSync待ちまたはその前後の実行経路を調べる。表示更新とRAM値の観測は別の証拠として扱う。
