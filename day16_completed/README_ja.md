## 📜 概要

今日は 6502 を非常に強力にしている機能の一つ、**インデックス付きアドレッシング**を実装します。

これはベースとなるアドレス（絶対アドレスなど）に、X レジスタまたは Y レジスタの値を加算した場所にアクセスするモードです。これにより、ループを使って配列やテーブルからデータを効率的に読み書きできるようになります。

## 🧠 メモリ構成の注意

Day 10 以降はプログラムを Gowin BSRAM で実装した RAM (`ram.sv`) から実行します。Day 04〜09 の簡易 ROM とは構成が異なります。CPU からは `$0000-$7FFF` が RAM、`$8000-$FFFF` が ROM に見え、リセット後に `boot_loader.sv` が ROM のブートイメージを RAM の `$0200` 以降へ 256 バイトコピーしてから実行が始まります。

## 🎯 学習目標

- **インデックス計算**: ベースアドレス + レジスタ値の計算タイミングの理解。
- **配列処理の基礎**: ループと X レジスタを組み合わせたプログラミング。
- **マルチサイクル処理**: アドレス計算によるクロック数の増加への対応。

## 🏗️ 実装する命令

```mermaid
graph LR
    Base[Base Address<br/>$1000]
    RegX[Register X<br/>$05]
    Adder{+}
    Eff[Effective Address<br/>$1005]
    Mem[Memory]

    Base --> Adder
    RegX --> Adder
    Adder --> Eff
    Eff -->|Access| Mem
```

| オペコード | ニーモニック | 説明                               | サイクル数 |
| :--------: | ------------ | ---------------------------------- | :--------: |
| `0xBD`     | `LDA abs,X`  | アドレス (abs + X) から A にロード | 4+         |
| `0xB9`     | `LDA abs,Y`  | アドレス (abs + Y) から A にロード | 4+         |
| `0x9D`     | `STA abs,X`  | A の値をアドレス (abs + X) に保存  | 5          |

※ サイクル数は実機 6502 の値です。`LDA abs,X` / `LDA abs,Y` はページを跨ぐと 1 サイクル増え、`STA abs,X` はページ跨ぎの有無にかかわらず 5 サイクルです。この教材 CPU はベースアドレスへの 16 ビット加算を 1 回で行う固定サイクル実装のため、ページ跨ぎによる追加サイクルはありません。

## 🛠️ 実装ステップ

1. **アドレス加算器の追加**:
    - フェッチした 16 ビットのベースアドレスに、X または Y レジスタの値を加算するロジックを実装します。
    - 例: `effective_address = base_address + X;`
2. **ステートマシンの調整**:
    - ベースアドレスの 2 バイト目をフェッチした後、加算を行ってからメモリアクセスを行うためのステート管理（あるいはパイプライン）を調整します。

## 🧪 動作確認

完成版 CPU テストはこのディレクトリで `make test-cpu` を実行します。共有スターターのテストベンチ `../day16/sim/tb_cpu.sv` が `LDA abs,X` / `LDA abs,Y` / `STA abs,X` の読み書きを検証します。`make test` はこれに加えて TFT smoke test (`test-lcd`)、同期 RAM 統合テスト (`test-sync`: ステップ周期 1/4/16 と手動ステップ)、LCD パイプライン検証 (`test-lcd-pipeline`) も実行します。`make sim` は TFT smoke test のみを実行します。テスト合格は assertion 範囲の確認であり、全命令や実機動作を保証しません。

- **テストプログラム**:

    ```asm
    ; 配列の内容を A に順番にロードする
    LDX #$00
    LOOP:
    LDA DATA,X ; DATA + X 番地からロード
    INX
    CPX #$03
    BNE LOOP
    HLT
    DATA: .byte $11, $22, $33
    ```

    これは完成版 `rom.sv` の命令列です（`LDA DATA,X` は `LDA $020B,X` にアセンブルされ、`DATA` は `$020B-$020D` に配置されます）。共有スターターのテストベンチはこれとは別のプログラムを注入します。

- **実機 (FPGA)**: LCD 上で A レジスタが `$11`、`$22`、`$33` と順次変化し、ループを抜けて最終的に `A=$33`, `X=$03` で停止することを確認します。実機では `lcd_demo.sv` の 24 ビットカウンタで `pc_enable` の発生間隔を調整し、CPU が低速実行されるためレジスタの変化を目で追えます。

## 🎯 次のステップ

Day 17 では、さらに高度な**間接アドレッシング (Indirect Addressing)**に挑戦します。ポインタ変数を使いこなすための、6502 の最難関モードです。

CPU 単体テストと実機 ROM では、実行するプログラムが異なります。表に示した実機での期待値は `rom.sv` と LCD の配線から判断した値であり、すべてのボードで実機確認を済ませたという意味ではありません。

同期 RAM に読み出しを要求してからデータを取り込むまでのタイミングは[同期RAMの説明](../docs/DAY18_TO_DAY99_ja.md#同期ramを読むときの時間)を参照してください。起動時は PLL LOCK を同期し、16 クロック連続で安定したことを確認してからブート処理を開始します。

LCD の VSync は表示書き込み側のクロックに 2 段のフリップフロップで同期させ、その立ち上がりでフレーム更新を開始します。VRAM とフォントの読み出しは、画素クロックの領域内で処理します。
